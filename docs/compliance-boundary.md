# 合规边界

本文定义项目的红线。任何实现、任何扩展都不得越过。

## 做什么

围绕**自有阵地**的自动化，以及**合规获客**：

- 自有频道和群的 AI 内容规划、写作、定时发布（发布前人工确认）。
- 自有群的官方 bot：新人欢迎、知识库 FAQ 答疑、反诈骗/反广告守护、裂变邀请链接追踪。
- 多员工总控收件箱：坐席分配、标签、AI 建议回复。
- 流量池 CRM：来源归因、跨群去重、用户分层、转化漏斗。
- 合规获客：
  - Telegram Ads 官方广告投放。
  - 与群主/频道主互推——AI 筛选候选频道（读公开信息）、评估质量、起草合作邀约，**由真人员工用真实账号发起和洽谈**。
  - 站外平台（X、小红书、YouTube、博客等）内容分发，附进群链接。
  - 裂变奖励：用邀请链接追踪拉新来源。
  - 以真人身份在允许的社区认真参与，个人简介放自有群链接。AI 可辅助起草，由人判断和发送。

## 不做什么

以下属于批量 spam 和规避平台检测，一律不做，也不提供实现：

- 多个账号冒充真人（养号、矩阵账号）。
- 批量自动进入他人社区。
- 在他人群里自动发布引流内容。
- 设备指纹伪装、IP/代理隔离、规避检测的发言节奏等"防风控"手段。
- 多开群控软件的选型或开发。
- 抓取非自己管理的私有频道内容。
- 任何多账号会话轮换（session pool / round-robin）的个人号自动化。

## 为什么

- 违反 Telegram 服务条款，账号会被限制或封禁。
- 被标记为 spam 后，自有群和频道会被连带降权，损害自己的核心资产。
- 骚扰的是他人社区的真实成员。
- 规模放大（n 台电脑 × m 个账号）不改变性质，只会放大问题。

## 技术约束（由边界派生）

- 对外只接**官方 Bot API token**，不接个人账号（MTProto user session）。
- "防风控"在本项目中仅指**保护自有群**（防广告刷屏、遵守 Bot API 速率限额），不指规避平台检测。
- 引入的第三方开源组件若包含多账号轮换、私有频道抓取等能力，不启用相关模块。

## 评估中据此排除的项目

- `lenin5558dif/telegram_crm`、`ItsOrv/Telegram-Panel`、`madara896/foggygramm`、`feel90d/chatwoot-messenger-gateway`：多个人号的群发、私信或群控，未拉取、未评估。
- `yevhens-hue/telegram-analytics`：抓取私有频道 + 多会话轮换，评为不建议使用。
