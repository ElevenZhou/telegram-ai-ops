# 系统架构

## 总览

系统分四层，全部围绕**自有阵地**（自己的频道、群、bot）运转，对外获客走合规渠道。

```
┌─────────────────────────────────────────────────────────────┐
│  获客层（合规）                                                │
│  Telegram Ads · 互推合作 · 站外内容分发 · 裂变邀请链接         │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  内容层                                                        │
│  TGhost：选题规划 → AI 写稿 → 人工审核 → 定时发布              │
│  数据回收：浏览、反应、评论、新增成员 → 回灌下一轮选题          │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  触点层（每个自有群/频道一个官方 bot）                         │
│  新人欢迎 · 知识库 FAQ 答疑 · 反诈骗/反广告 · 裂变追踪         │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  总控与沉淀层                                                  │
│  Chatwoot：多员工收件箱、坐席分配、标签、AI 建议回复          │
│  流量池 CRM（自研）：来源归因、跨群去重、分层、转化漏斗        │
└─────────────────────────────────────────────────────────────┘
```

## 各层职责

### 获客层
把相关人群引到自有群。只用合规手段：官方广告、与群主/频道主的互推（AI 筛选并起草邀约，员工用真人账号去谈）、站外平台内容分发、裂变奖励。

### 内容层
按"多个方向"分垂直赛道，每个方向一套选题日历和话术。TGhost 负责 AI 写稿和定时发布，发布前人工确认。发布后的数据回收用于下一轮选题。

### 触点层
每个自有群/频道配一个官方 bot，承担入群引导、知识库答疑、群内秩序维护（反诈骗、反广告）、以及裂变邀请链接的归属追踪。

### 总控与沉淀层
- **Chatwoot** 作为多员工总控台，所有群/频道的私聊和工单汇聚到统一收件箱，支持坐席分配、标签、私有备注和 AI 建议回复。
- **流量池 CRM（自研）** 是业务核心资产：记录每个用户的来源渠道和邀请链接、跨群去重、打标签分层、跟踪转化漏斗。开源项目无合适替代，需自研。

## 数据流

1. 用户从获客渠道点击邀请链接 → 进入某个自有群。
2. 群内 bot 记录来源（渠道、链接 ID），写入流量池 CRM。
3. 用户互动（提问、私聊）→ 汇入 Chatwoot 收件箱，员工或 AI 处理。
4. 内容层定时推送 → TGhost 回收互动数据。
5. 流量池 CRM 汇总来源、互动、转化，产出分层和漏斗，回灌给获客和内容决策。

## 技术栈建议

| 层 | 组件 |
|---|---|
| 内容层 | TGhost（Python + 前端），Claude API 负责规划和写作 |
| 触点层 | 官方 Bot API，`aiogram` / `python-telegram-bot`，susmessagebot 做守护 |
| 总控层 | Chatwoot（Rails + Postgres + Redis），Docker 部署 |
| 流量池 | 自研，建议 Postgres，数据模型基于 Chatwoot 联系人与标签扩展 |

## 部署原则

- 所有组件用 Docker 隔离部署。
- 对外只接**官方 bot token**，不接任何个人账号（MTProto）。
- 第三方开源组件上生产前先做代码审计，确认无数据外发逻辑。
