# 落地路线

分三阶段，先立底座（总控 + 流量池 + 自有群 bot），再接内容和获客。

## 阶段一：底座（约 1 周）

目标：不管流量从哪来，都能落到自己手里并沉淀。

- [ ] Docker 隔离环境部署 Chatwoot CE，接 1 个官方 bot token，验证收件箱、坐席分配、标签。
- [ ] 流量池 CRM 最小版：用户、来源渠道、邀请链接归属、标签。数据模型基于 Chatwoot 联系人扩展。
- [ ] 自有群配官方 bot：新人欢迎 + 邀请链接来源记录写入 CRM。
- [ ] susmessagebot 代码审计（确认无数据外发），在一个自有群试运行反诈骗守护。

## 阶段二：内容中台（约 1 周）

目标：多方向内容自动规划和发布。

- [ ] Docker 试跑 TGhost，接自有频道，验证 AI 写稿 + 定时发布 + 人工确认流程。
- [ ] 接 Claude API 做选题规划，按方向建选题日历。
- [ ] 知识库 FAQ：群内 bot 基于知识库自动答疑，命中率不足转人工（进 Chatwoot）。
- [ ] TGhost 单用户限制的应对：要么只做内容侧，要么补一层多员工权限。

## 阶段三：获客与放大（约 1 周）

目标：合规地把相关人群引进来，并追踪效果。

- [ ] Telegram Ads 投放管理：按方向建广告、记录各渠道带来的进群和转化。
- [ ] 互推线索库：AI 读公开信息筛选候选频道、评估质量、起草邀约；员工用真人账号洽谈。
- [ ] 裂变奖励闭环：邀请链接 → CRM 归属 → 奖励发放。
- [ ] 数据看板：各方向、各渠道的进群、活跃、转化漏斗。

## 里程碑验收

| 阶段 | 验收标准 |
|---|---|
| 一 | 一个自有群的新成员能被 CRM 记录来源并自动打标签；私聊能在 Chatwoot 处理。 |
| 二 | 一个方向的内容能 AI 起草、人工一键确认、定时发布，并回收互动数据。 |
| 三 | 能说清每个新客户来自哪个渠道/链接，并看到各方向的转化漏斗。 |

## 说明

- 规模（n 台电脑 × m 个账号）的放大不在本路线内——那依赖被排除的群控能力。本路线做的是把自有阵地做深、把来源做清楚。
- 每阶段第三方组件上生产前先审计，详见 [compliance-boundary.md](compliance-boundary.md) 的技术约束。
